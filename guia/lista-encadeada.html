Lista encadeada

Nós ligados por referências, sem posições contíguas. A lista simples anda em um sentido; a dupla, nos dois.

3 exemplos · inserir no início O(1) · buscar O(n)

O que é

Uma lista encadeada é uma sequência de nós. Cada nó guarda um valor e uma referência para o próximo nó. O primeiro é o head; o último aponta para ∅ (null ou undefined). Não há posições contíguas: os nós podem estar espalhados na memória e a ordem existe só pelas referências.

Na lista simples, cada nó tem valor e proximo. Na dupla, cada nó também tem anterior, o que permite andar para trás e manter head e tail. Em troca, cada nó gasta um ponteiro a mais.

Como funciona

  • Inserir no início — cria o nó, aponta o proximo para o antigo head e atualiza o head. O(1).
  • Inserir no fim — O(1) se você mantém o tail; sem tail, é preciso caminhar até o último nó (O(n)).
  • Remover por valor — encontrar o nó é O(n); religar o anterior no próximo é O(1).
  • Percorrer — O(n): atual = atual.proximo até o terminador.

O invariante: o proximo do último é o terminador, e o anterior do primeiro (na dupla) também. Se você perder uma referência antes de religar, o resto da lista fica inalcançável.

const no2 = { valor: 20, proximo: null };
const no1 = { valor: 10, proximo: no2 };
let inicio = no1;
inicio = { valor: 5, proximo: inicio };
console.log(inicio.valor);          // 5
console.log(inicio.proximo.valor);  // 10

Custo

Com n nós na lista:

Custo das operações com n nós
OperaçãoCustoObservação
Acesso por posição / buscaO(n)Não há índice: é preciso caminhar pelos ponteiros.
Inserir no inícioO(1)Cria o nó e atualiza o head.
Inserir no fimO(1) com tail; O(n) sem tailSem a referência do último, é preciso percorrer a lista.
Remover no inícioO(1)O head passa para o próximo nó.
Remover por valorO(n) para encontrar + O(1) para religarA busca domina o custo; religar os ponteiros é barato.
MemóriaO(n)Um ponteiro por nó na simples; dois na dupla, além do valor.

A vantagem não é ser “mais rápida” em tudo: é trocar o deslocamento do array por ponteiros. Se o acesso por posição domina, o array ganha.

Quando usar

Use quando inserir e remover nas pontas é frequente e o tamanho é imprevisível:

  • Pilha e fila encadeadas: push/pop no head ou enqueue/dequeue com head e tail em O(1).
  • Listas de tarefas e históricos: remover um item do meio sem deslocar o resto.
  • Estruturas compostas: listas de colisão em tabelas hash, listas de adjacência em grafos.
  • LRU e caches: a lista dupla combina remoção O(1) com um mapa para localizar o nó.

Quando evitar

  • Acesso por índice ou busca frequente: cada consulta é O(n).
  • Varredura sequencial intensa: o array tem melhor localidade de cache.
  • Você precisa ordenar por posição: o array é mais simples.

Erros comuns

Antes de rodar
  • Perder o proximo antes de religar. Salve o próximo em uma variável temporária antes de mudar o ponteiro.
  • Esquecer de atualizar o head ao inserir no início e ao remover o primeiro nó.
  • Na lista dupla, atualizar só o proximo e esquecer o anterior do nó seguinte.
  • Usar um for com índice como se a lista fosse um array; aqui o caminho é atual = atual.proximo.
  • Confundir o terminador null/undefined com um nó vazio: ele não conta no tamanho.
  • Remover um nó e continuar usando a referência dele; o resto da lista pode ficar inalcançável.
