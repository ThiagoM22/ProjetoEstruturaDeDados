Árvore binária

Cada nó tem até dois filhos. Na árvore binária de busca, a ordem permite descartar um lado a cada comparação.

6 exemplos · busca O(log n) média · O(n) no pior caso

O que é

Uma árvore binária é uma estrutura hierárquica em que cada nó tem no máximo dois filhos: esquerda e direita. O nó do topo é a raiz; nós sem filhos são folhas; cada nó com seus descendentes forma uma subárvore. A altura é o comprimento do caminho mais longo da raiz até uma folha.

Uma árvore binária de busca (BST) acrescenta uma regra de ordem: para todo nó, os valores menores ficam à esquerda e os maiores à direita. Neste projeto, valores iguais vão para a direita. Isso permite buscar, inserir e remover descartando um lado inteiro a cada comparação — mas só se a árvore estiver razoavelmente equilibrada.

Como funciona

  • Buscar/inserir: compare com o nó atual; menor vai à esquerda, maior (ou igual) à direita. O custo é O(h), onde h é a altura.
  • Percorrer: em-ordem (esquerda, raiz, direita) devolve os valores em ordem crescente na BST; pré e pós-ordem servem para copiar, serializar e avaliar expressões.
  • Remover: folha ou um filho são casos diretos; com dois filhos, o sucessor é o menor nó da subárvore direita (ou o antecessor, o maior da esquerda).
  • Recursão: os percursos descem e voltam; a pilha de chamadas do EDViz mostra esse caminho.

O ponto delicado é o equilíbrio. Uma BST construída em ordem crescente vira uma lista: a altura é n e a busca é O(n). Árvores balanceadas (AVL, rubro-negra) garantem O(log n) no pior caso; a BST simples não.

class No {
  constructor(v) {
    this.valor = v;
    this.esquerda = null;
    this.direita = null;
  }
}
const raiz = new No(50);
raiz.esquerda = new No(30);
raiz.direita = new No(70);
console.log(raiz.esquerda.valor); // 30

A tabela só é honesta com a altura: uma BST comum pode ter h = n. Inserir 1, 2, 3, 4, 5 em ordem crescente produz uma corrente, não uma árvore equilibrada.

Quando usar

Use quando a ordem dos dados é parte do problema:

  • Busca ordenada: encontrar, inserir e remover mantendo a ordem.
  • Percursos ordenados: o em-ordem da BST devolve os valores em ordem crescente.
  • Consultas por intervalo: “todos os valores entre 30 e 70” sem varrer a estrutura inteira.
  • Índices e dicionários ordenados: bancos de dados e mapas que precisam de ordem, não só de igualdade.

Quando evitar

  • Você só precisa de igualdade (chave → valor): uma tabela hash é mais direta.
  • Precisa sempre do menor/maior: um heap resolve com menos estrutura.
  • Os dados entram em ordem crescente e você não vai balancear: a BST degenera.
  • O acesso é sequencial e a localidade de cache importa: o array ganha.

Erros comuns

Antes de rodar
  • Inverter a regra: menores à esquerda, maiores ou iguais à direita. Comparar com o nó errado produz uma árvore que parece BST, mas não é.
  • Confundir árvore binária simples com BST: a simples só limita os filhos; a BST impõe a ordem.
  • Inserir duplicados sem uma regra. Neste projeto, os iguais vão para a direita; em outra implementação, podem ser recusados.
  • Remover um nó com dois filhos sem o sucessor (menor da direita) ou o antecessor (maior da esquerda); o buraco quebra a busca.
  • Esquecer de atualizar o ponteiro do pai ao remover ou promover um filho.
  • Esperar equilíbrio de uma BST comum. Se a entrada é ordenada, a altura vira O(n).
  • Recursão sem caso-base: a pilha de chamadas cresce até o limite (no EDViz, 500 chamadas).
