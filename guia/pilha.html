Pilha

O último elemento que entra é o primeiro que sai. Push e pop acontecem sempre no topo — e é isso que o desenho mostra.

2 exemplos · push/pop O(1) · acesso ao topo O(1)

O que é

Uma pilha é uma coleção linear em que inserções, remoções e leituras acontecem em uma única extremidade: o topo. O elemento mais antigo fica na base; o mais recente, no topo. Por isso a regra é LIFO — last in, first out: o último que entra é o primeiro que sai.

A metáfora clássica é a pilha de pratos: você põe e tira sempre de cima. A pilha não oferece acesso por índice; para chegar ao meio, é preciso desempilhar o que está acima. Essa restrição é a característica da estrutura, não uma limitação a contornar.

Como funciona

As operações essenciais são:

  • push(x) / empilhar — coloca x no topo; o tamanho aumenta em 1.
  • pop() / desempilhar — remove e devolve o topo; o tamanho diminui em 1.
  • peek() / topo — devolve o topo sem remover.
  • isEmpty() / estaVazia e size() / tamanho — consultam o estado.

O invariante: os elementos abaixo do topo não se movem quando você empilha ou desempilha. A pilha só muda na extremidade.

const pilha = [];
pilha.push(10);            // base
pilha.push(20);
pilha.push(30);            // topo
console.log(pilha.pop());  // 30
console.log(pilha.length); // 2

Com um array, o topo é o fim (push/pop). Com uma lista encadeada, o topo é o início (head), e as duas operações continuam O(1). A classe Pilha apenas esconde o array interno atrás de métodos — a regra LIFO é a mesma.

Custo

Com n elementos na pilha:

Custo das operações com n elementos
OperaçãoCustoObservação
push(x)O(1) amortizadoNo array dinâmico, uma expansão ocasional custa O(n); na lista encadeada, O(1).
pop()O(1)Remove e devolve o topo.
peek() / topoO(1)Só lê o topo, sem remover.
isEmpty() / size()O(1)Consulta o estado.
Busca por valorO(n)Percorre do topo à base; a pilha não é feita para busca.
Acesso por índiceO(1) no array internoFora da API da pilha; se precisa disso, provavelmente quer um array.
MemóriaO(n)O array pode reservar capacidade extra; a lista gasta um ponteiro por nó.

O custo amortizado é o que importa na prática: N pushes custam O(N) no total, mesmo que um deles seja O(n).

Quando usar

Use quando a ordem de processamento precisa ser a reversa da chegada:

  • Desfazer e refazer: uma pilha guarda as ações feitas; outra, as desfeitas.
  • Chamadas de função e recursão: cada chamada empilha um quadro; o retorno desempilha.
  • Expressões e parênteses: validar aninhamento e avaliar notação pós-fixa.
  • DFS e backtracking iterativo: guardar o próximo caminho a explorar.

Quando evitar

  • Precisa atender por ordem de chegada? A estrutura é uma fila.
  • Precisa acessar ou buscar no meio com frequência? Um array ou uma lista é mais direto.
  • Precisa sempre do menor ou do maior elemento? Use um heap / fila de prioridade.

Erros comuns

Antes de rodar
  • Usar shift() para “tirar do topo”. Em um array, o topo é o fim: pop() remove o último; shift() remove o primeiro e transforma a pilha em fila.
  • Chamar pop() ou peek() sem verificar se a pilha está vazia. No EDViz, pop() em vazio devolve undefined; em Java e C#, a operação lança exceção. Veja o passo 10 do exemplo.
  • Ler pilha[0] achando que é o topo. O topo é pilha[pilha.length - 1].
  • Confundir LIFO com FIFO: se a saída precisa respeitar a ordem de chegada, a estrutura é uma fila.
  • Em uma implementação manual, esquecer de atualizar o tamanho ou o topo ao remover. O MeuArray mostra por que #items.length e #tamanho são coisas diferentes.
